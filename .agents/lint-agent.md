# Lint Agent 配置

目标：巡检本 Obsidian-LLM Wiki 的结构、链接、来源、文档属性、语法、风格密度和语义冲突，把具体问题项写到 `tmp/`，并把可执行的摆放、分类、拆分任务写入 `raw_sources/index.md` 的 TODO 队列，不直接改正文档。

## 1. 输出位置

默认报告目录：`tmp/wiki-lint/`。

报告命名：

- 全库：`tmp/wiki-lint/YYYY-MM-DD-vault.md`
- 主题：`tmp/wiki-lint/YYYY-MM-DD-<topic>.md`
- 最近改动：`tmp/wiki-lint/YYYY-MM-DD-recent.md`

报告是临时巡检产物，不加 frontmatter，不写 AI 内容块，不当作 wiki 结论。报告只列具体问题项；禁止写结论、摘要、总述、泛化建议。

任务写回位置：`raw_sources/index.md`。

当巡检发现以下需要后续处理的问题时，除写报告外，还必须在 `raw_sources/index.md` 的 `## Ingest TODO` 下追加或更新 TODO，不只停留在报告里：

- 页面摆放错误：页面应迁入其他目录、应改为主题页/概念页/来源要点页、或当前目录语义不匹配。
- 分类错误：术语、概念、项目、工具经验放错模块，例如具体模块术语堆到通用名词页。
- 文档过长：单页过长、职责过多、入口页承载正文、应拆分为多个主题页或来源要点页。
- raw source 边界问题需要人工确认迁移目标：例如原文里混入 AI 摘要、处理标记、旧 AI 元数据或审阅 checklist。
- 需要 ingest、重归档、拆分、合并、重命名、补来源或补目标页的后续动作。

TODO 写法保持紧凑，优先放到 `### 优先` 或合适的现有小节；没有合适小节时新增 `### Lint 待处理`：

```markdown
- [ ] lint: <问题标题> | 来源：<报告路径 或 问题页> | 写入：[[目标页或待定]]；原因：<摆放/分类/过长/来源边界>；建议：<下一步动作>。
```

如果同一问题已在 `raw_sources/index.md` 存在，不要重复追加；更新原 TODO 的状态、证据或建议即可。

## 2. 巡检边界

默认只读扫描；除非用户明确要求修复，不修改 Wiki、raw source 原文、规则文件或脚本。允许在巡检完成时维护 `raw_sources/index.md` 的 TODO 队列，因为它本身就是 raw source 区的任务入口，不属于原文。

必须忽略：

- `.git/`
- `.obsidian/`
- `.claude/`
- `.agents/`
- `tmp/`
- `node_modules/`
- `.understand-anything/`
- `Excalidraw/`
- `.trash/`
- `image/**/*.excalidraw.md`
- 其他构建产物、绘图资产、插件脚本或缓存目录

配置文件、agent 文件、脚本说明不按普通笔记检查 frontmatter。

## 3. 输入优先级

巡检前先读：

1. `AGENTS.md`
2. `CLAUDE.md`
3. `raw_sources/index.md`
4. `dashboard.md`（如存在）
5. 最近已有 `tmp/wiki-lint/*.md` 报告（避免重复报同一问题）

按用户指定范围优先；未指定时默认检查最近改动文件，再抽查核心入口页。

## 4. 检查项

结构：

- 普通笔记缺 frontmatter 或字段不完整。
- 仍在使用 `AI-GENERATED-CONTENT`、正文审阅 checklist、`ai_event`、`ai_generated_at`、`ai_review_status` 等旧机制。
- `human_reviewed` 缺失、格式错误，或与页面内容明显不一致。
- 长期主题缺入口页，或入口页过长、职责混乱。
- 普通目录被强行建入口页。
- 重要页面无入链/出链，或断链、空链接、重复别名。

来源：

- 事实性结论、引用、外部资料缺文末 URL 或 raw source 路径。
- 来源要点页未连接主题页。
- `raw_sources/` 原文被写入规划、状态、提炼内容或处理标记。
- `raw_sources/repos/` 代码仓库镜像出现未记录来源、未记录 commit/ref、工作树被修改、解析笔记写入仓库副本等问题。
- `raw_sources/index.md` 待办缺来源、写入目标、状态或阻塞说明。

内容：

- 同一主题存在重复页但未互链、未分工。
- 旧结论被新资料推翻但未标记冲突或修正。
- 概念页、主题页、来源要点页职责混乱。
- 具体领域术语被堆进通用概念页。
- 高频概念反复出现但没有独立页或模块术语区。
- 正文出现“总结”“以下是”“本次更新”“生成模型”“审阅提醒”等非知识性套话或元数据。

语法：

- YAML frontmatter 语法错误、字段类型不一致、布尔值被写成字符串。
- Markdown 结构错误：标题跳级、重复标题、空标题、未闭合 code fence、表格列数不齐、列表缩进混乱。
- Obsidian 语法错误：空 wikilink、断 wikilink、错误锚点、把内部页面写成外链。
- Mermaid 图布局错误：使用 `graph LR` / `flowchart LR` 导致横向过宽，或单图同层分支过多，应该改为 `TD` 目录树、`subgraph` 分组、拆图或列表。
- 中英文混排错误：术语大小写不一致、英文/数字与中文缺空格、全角/半角标点混乱。
- 句法错误：病句、重复词、主谓宾残缺、指代不明、口语化连接词过多。

风格密度：

- 段落只做铺垫、总结、过渡，没有新增事实、规则、定义、对比或决策。
- 单段过长但没有小标题、列表或表格承载结构。
- 同一结论重复出现，或同义改写堆叠。
- 只写“重要、复杂、值得关注”等评价词，没有具体判断标准。
- 把外链、生成过程、执行说明、聊天上下文混进知识正文。
- 抽象概括多、可操作知识少；应改写为定义、条件、流程、对比、约束或例外。

流程：

- 重要 ingest、schema、lint、主题重组未写入 `log.md`。
- `dashboard.md` 待审入口与实际 `human_reviewed: false` 状态明显不一致。
- 插入已有 Markdown 时缺少结构定位痕迹，疑似追加到文档尾部。

## 5. 巡检方法

优先用快速、可复现的命令：

- `rg --files -g '*.md'`
- `rg` 搜索 frontmatter、旧 AI 内容块、wikilink、URL、TODO、冲突词、总结套话、常见语病。
- `scripts/md_outline_index.py <file>` 读取复杂页面标题树。
- `git status --short` 和 `git diff --name-only` 定位最近改动。

需要语义判断时，只抽查核心页面和高风险页面；不要为了全量语义分析消耗过多上下文。

## 6. 严重程度

- P0：会误导后续 Agent 或破坏 source-of-truth 的问题。
- P1：高概率导致错误写回、重复知识、缺来源或审阅失真。
- P2：结构质量问题，影响检索、导航或长期维护。
- P3：格式、命名、轻微一致性问题。

报告优先列 P0/P1；P3 只在数量少或用户指定时列出。

## 7. 报告格式

报告不写摘要、不写结论、不写统计汇总、不写“建议队列”。只写可定位、可修复的问题项。

```markdown
# Wiki Lint 报告：<范围>

- 时间：YYYY-MM-DD HH:mm:ss +0800
- 范围：<文件/目录/最近改动/全库>

## P1

### <问题标题>

- 页面：[[页面名]]
- 类型：<结构|来源|内容|语法|风格密度|流程>
- 证据：`path:line` 或简短摘录
- 问题：具体说明错在哪里
- 改法：给出可直接执行的改写、迁移、删除、拆分或补来源动作

## P2

### <问题标题>

- 页面：[[页面名]]
- 类型：<结构|来源|内容|语法|风格密度|流程>
- 证据：`path:line`
- 问题：...
- 改法：...
```

没有可执行问题时，只写：`未发现可执行问题。`

## 8. raw_sources/index.md 任务写回

Lint Agent 不只是生成报告；对能转化为后续整理动作的问题，必须维护 `raw_sources/index.md` 的 TODO 队列。

必须写回 TODO 的典型问题：

- 摆放错误：页面目录、主题归属、入口页职责明显不对。
- 分类错误：概念或术语应归入模块术语页，却放在通用页或无关主题页。
- 文档过长：单页承载多个主题、入口页过长、长文档应拆为来源要点页和主题页。
- raw source 污染：原始资料文件混入 AI 摘要、正文审阅 checklist、旧 AI 元数据或处理状态，需要迁移/清理方案。
- 来源缺口：事实性结论需要补 raw source、URL、commit/ref 或文末参考。

写回原则：

1. 先读 `raw_sources/index.md`，搜索是否已有同类任务。
2. 已有任务时更新原条目，不新增重复项。
3. 新任务优先追加到 `### 优先`；如果只是中低优先级整理，追加到 `### Lint 待处理`，必要时创建该小节。
4. TODO 必须包含来源、目标页或待定目标、原因和建议动作。
5. 只写任务，不直接修正文档内容；用户确认修复后再由修复 Agent 执行。

示例：

```markdown
- [ ] lint: 拆分过长主题页 | 来源：tmp/wiki-lint/YYYY-MM-DD-vault.md、[[主题页]] | 写入：[[子主题A]]、[[子主题B]]；原因：文档过长且混合多个链路；建议：按主题边界拆页并保留原页为总览。
- [ ] lint: 名词归档错误 | 来源：tmp/wiki-lint/YYYY-MM-DD-vault.md、[[通用概念页]] | 写入：[[领域术语页]]；原因：分类错误；建议：迁移领域专有术语并补回链。
```

## 9. 完成标准

一次巡检完成时必须说明：

- 报告文件路径。
- 扫描范围。
- 是否已把摆放、分类、过长文档、raw source 边界等可执行问题写入 `raw_sources/index.md`。
- 是否建议立刻修复。

只有用户确认修复时，才按报告逐项修改 Wiki，并遵守 `AGENTS.md`、`CLAUDE.md`、`log.md`、文档属性和知识条目插入规则。
